1. SCOPE AND NON-GOALS

This phase implements fixed-size storage and index access only.
It does not implement metric differentiation, matrix inversion, Christoffel
symbols, Riemann, Ricci, scalar curvature, Einstein tensors, CAPD adapters,
interval arithmetic, or certification.

No analytical Einstein reference values are included in the storage header
or storage tests. The III-B.3 analytical reference remains reserved for a
future independent validation harness.

2. FIXED COORDINATE AND INDEX CONTRACT

N = 4
Coordinate order: (T, x, theta, phi)
0 = T
1 = x
2 = theta
3 = phi

The C++ enum class Coordinate encodes exactly these values. The helper
index(Coordinate) converts a semantic coordinate to its numeric index.

3. TYPES AND STORAGE SHAPES

Vector4<Scalar> = std::array<Scalar, 4>
Matrix4<Scalar> = Scalar[4][4]
Tensor3_4<Scalar> = Scalar[4][4][4]
Tensor4_4<Scalar> = Scalar[4][4][4][4]

MetricJet<Scalar> contains:
  g   : Matrix4<Scalar>
  dg  : Tensor3_4<Scalar>
  ddg : Tensor4_4<Scalar>

Semantic meanings:
  g(mu,nu) = g_mu_nu
  dg(a,mu,nu) = partial_a(g_mu_nu)
  ddg(a,b,mu,nu) = partial_a(partial_b(g_mu_nu))

Logical element counts:
  g   = 16
  dg  = 64
  ddg = 256
  total MetricJet scalar slots = 336

All storage is fixed-size std::array-based storage. No dynamic allocation
is required for the tensor payload. Value initialization sets entries to
the Scalar default value.

4. INDEX ACCESS AND SAFETY

Numeric access is provided through operator():
  matrix(mu,nu)
  tensor3(a,mu,nu)
  tensor4(a,b,mu,nu)

Semantic overloads accept Coordinate values in the same position order.
Every access uses std::array::at, so an index outside [0,3] throws
std::out_of_range instead of silently accessing invalid memory.

Storage order is fixed and identical across the types:
  Matrix4:   [mu][nu]
  Tensor3:   [a][mu][nu]
  Tensor4:   [a][b][mu][nu]

No implicit index permutation, tensor symmetry compression, or packed
storage is used. All 16/64/256 ordered slots exist independently.

5. BACKEND INDEPENDENCE

The storage templates are parameterized by Scalar and do not include CAPD
headers or depend on a particular numeric backend. The concrete
DiagnosticScalar alias is double for this first diagnostic build.
A long double instantiation is compile-tested.

Template genericity is a storage-level property only. It does not prove
that an interval scalar can be substituted safely: interval arithmetic,
outward rounding, division semantics, expression dependencies, and
CAPD API compatibility remain separate work.
