============================================================
2. SOURCE FACTS
============================================================

2.1 Configuration objects

Volume II, Section III.4, states:
C = (S_C,#_C)
S_C subseteq U0
#_C = # restricted to S_C x S_C.

It states that a minimal nontrivial configuration satisfies |S_C| >= 2, while exact admissibility conditions remain realization-dependent.

Volume III, Section 6, gives a nontriviality test requiring:
|S_C| >= 2
and
there exist x,y in S_C such that x #_C y.

This is a nontriviality test. The source does not declare it to be the complete admissibility predicate Adm(C) for every realization.

2.2 Candidate embeddings and category morphisms

Volume II, Section III.5, defines an embedding f:C1 -> C2 as injective and preserving and reflecting the selected apartness:
x #1 y iff f(x) #2 f(y).

Volume II describes C_METACORE as a category whose objects are admissible configurations and whose morphisms preserve selected structural properties.

The source does not explicitly identify:
- every candidate apartness embedding with a C_METACORE morphism;
- literal inclusions as the only C_METACORE morphisms;
- a restricted subclass defined by a precise predicate P(f);
- restrictions of global automorphisms as the C_METACORE morphisms.

Thus the local embedding definition is available, but the exhaustive morphism class of C_METACORE is not.

2.3 Compatibility and amalgamation

Volume II, Section IV.1, states:
CC(C1,C2) = 1 iff an admissible amalgamation of C1 and C2 exists.

The inspected definition does not fully specify whether this is:
(A) pair-based common embeddability, where C1 and C2 embed into some common admissible object; or
(B) span-based amalgamation, where a specified span C0 -> C1 and C0 -> C2 must be jointly completed.

For the span-based interpretation, the source does not define the complete input data:
C0, f1:C0 -> C1, f2:C0 -> C2,
nor the required commuting equation:
j1 o f1 = j2 o f2.

The inspected source also does not settle whether an amalgam object must be:
- an abstract newly constructed carrier; or
- an induced subconfiguration of the same fixed U0.

2.4 Diagram and colimit

Volume II, Sections IV.2-IV.3, defines R := colim(D_CC) only where the required categorical construction exists. It makes existence conditional on a valid compatibility diagram, the relevant categorical structure, and existence of the colimit or an equivalent constraint-preserving construction.

Volume III, Sections 8-9, is explicit:
D_CC alone is not a complete categorical construction.
The specification must include:
- an indexing category J;
- a functor D:J -> C_METACORE;
- the relevant objects and morphisms;
- compatibility conditions;
- the required universal property.

The inspected sources do not instantiate these data for a particular project-level D_CC.

============================================================
4. MATHEMATICAL CONSEQUENCES OF THE GAP
============================================================

4.1 The category choice changes the theorem

The existing comparison records establish that different test categories can yield different colimit behavior:
- In the inclusion-only category P_F, the union is a colimit when it is an admissible object.
- In the explicitly defined fixed-carrier all-embeddings category E_F, S2-04C-10 proves that its specified finite span has no pushout.

These are not contradictory results. The categories have different morphism classes and therefore different universal-property tests.

4.2 Weak amalgamation is not a colimit theorem

Existence of some admissible common target does not, by itself, establish a pushout or a general colimit. A colimit requires a specified diagram and a universal property relative to all cocones in the declared category.

4.3 No project-level positive or negative colimit conclusion follows yet

Because the inspected project sources do not identify the intended C_METACORE, do not specify the complete admissibility predicate, and do not instantiate J and D, neither of the following is currently established:
- a project-level theorem that R = colim(D_CC) exists;
- a project-level theorem that R = colim(D_CC) does not exist.

The finite E_F obstruction remains valid only within its explicitly defined test category.
