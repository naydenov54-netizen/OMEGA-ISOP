4. CORRECTION TO THE CC TEST CONTRACT
============================================================

The previous comparative test defined CC_M through existence of any categorical cocone whose two legs are M-morphisms.

This is not safe as a general definition of the canonical CC predicate.

Canonical source definition:
CC(C1,C2)=1 iff an admissible amalgamation exists.

A candidate category may have non-injective homomorphisms. If arbitrary homomorphism cocone legs are allowed to count as admissible amalgamation legs, the category change can broaden CC by admitting identifications that the source-level amalgamation concept may prohibit.

Corrected separation:

A. SOURCE-LEVEL ADMISSIBLE AMALGAMATION:
Define AdmAmalg(C1,C2) using the exact source admissibility requirements, including the required configuration maps and inherited structural constraints.

Then:
CC_source(C1,C2)=1 iff AdmAmalg(C1,C2) is nonempty.

B. CATEGORICAL COCONE:
Define Cocone_M(D,Q) using the morphisms of the selected category M.

C. UNIVERSAL PROPERTY:
A pushout is tested against every cocone admitted by M.

These are distinct notions.
A categorical cocone in a homomorphism category is not automatically an admissible amalgamation for canonical CC.

For the already tested finite example, P_gen has source maps j1,j2 whose induced apartness structures on S1 and S2 are exact; hence it is an admissible strong amalgam under the tested apartness rules. The homomorphism pushout result remains valid.
The correction concerns the general CC test and prevents an invalid inference from arbitrary homomorphism cocones.

The cross-category CC comparison must now test:
CC_source(D) against the existence of at least one source-admissible amalgam in the candidate realization, not merely the existence of an arbitrary candidate-category cocone.

5. MIXED MORPHISM CLASS: SOURCE-GROUNDED INSTANTIATION TEST
============================================================

The earlier mixed proposal partitions a relational signature:
Sigma = Sigma_protected union Sigma_weak.

For protected relations rho:
rho_X(xbar) iff rho_Y(f(xbar)).

For weak relations sigma:
sigma_X(xbar) => sigma_Y(f(xbar)).

This is a valid abstract design pattern only after the signature and its protected/weak partition have been independently specified.

Current configuration signature in Volume II is:
C=(S,#_C).

There is one selected apartness relation # in this configuration signature.

For this single relation there are two source-distinct contracts:

CASE E:
x #X y iff f(x) #Y f(y).
This is exactly the explicit configuration-embedding contract.

CASE H:
x #X y => f(x) #Y f(y).
This is a weaker homomorphism contract and does not reflect apartness.

There is no source-defined second relation symbol or typed partition of # that would support a nontrivial protected/weak split within the current configuration signature.

One could add labels, colors, subrelations, pair-types, or a decomposition of # into protected and weak components. But that would enlarge or alter the relational signature and is not authorized by the inspected source clauses.

Therefore:
MIXED CLASS AS A GENERAL TEMPLATE: MATHEMATICALLY DEFINABLE.
MIXED CLASS AS A CANONICAL C_METACORE CATEGORY FROM THE CURRENT SIGNATURE: NOT INSTANTIATED.
MIXED CLASS AS A ROUTE TO FORCE A PUSHOUT: NOT JUSTIFIED.

If apartness # is protected by the source's explicit iff contract, the mixed class collapses to the embedding condition for the present signature.
If apartness # is weakened to forward preservation only, the mixed class collapses to the homomorphism condition for the present signature.
A genuinely intermediate class requires additional typed structural data.

7. A(R;Phi): CATEGORY-LEVEL INFORMATION IS INSUFFICIENT
============================================================

The inspected sources define:
Phi:Real(R)->M
A(R;Phi) subseteq Evol(X).

They do not define a general transport law taking a morphism of compatibility diagrams to:
- a map between realization spaces;
- a compatible transformation between selected Phi maps;
- a map between state spaces;
- a transport of admissible evolutions;
- a reflection theorem for admissibility.

The dynamic notation Aut(X,R) and End(X,R) is realization-dependent and may be used only after its objects, morphisms and preservation conditions are explicitly defined.

Thus the D_CC morphism class and the dynamic endomorphism class must remain separate until a bridge is proved.

To establish A(R;Phi) preservation under a diagram morphism or an alternative R construction, a realization-specific bridge is required. At minimum it must specify:
1. the source and target realizations;
2. the state-space transport;
3. compatibility/naturality of Phi;
4. transport of Evol(X);
5. preservation of membership in A(R;Phi);
6. reflection as well, if equivalence rather than one-way admissibility is claimed.

For stochastic dynamics, the separate coherent-lift and operational-closure requirements from the prior stochastic audit remain in force.

No candidate E, H or M passes this bridge merely by satisfying its relational morphism condition.
